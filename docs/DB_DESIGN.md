# DB Design (Normalized Relational Schema)

This document derives a production-ready relational database design from the endpoints described in `DETALLES.md`.

Schedule ingestion is based on a merged model:

- Student Records HTML (`tabla_guia_horario`) is the primary source for schedule listings per campus/program/period and provides classroom, capacity, reserved seats count, and professor display names.
- Guía de Horarios (`getdatosEscuelaAno`) is used to enrich schedule rows with meeting weekday/time records and reservation targeting metadata (campus/unit/plan). This endpoint is queried by school (`escuela`) and year (`ano`) and returns rows that include term components (`NUM_ANO`, `IDE_MODALIDAD`, `IDE_PER_MOD`).

Guía de Horarios rows are normalized to the same term key format used by Student Records and stored in `academic_term.external_key`:

- `{NUM_ANO}_{IDE_MODALIDAD}_{IDE_PER_MOD}` → e.g. `2026_S_1`

The merge join key used for enrichment is:

- campus code
- course code
- group code
- term key (`academic_term.external_key`)

## Source endpoints (sync origins)

### Guía de Horarios API (tec-appsext)
- `POST /guiahorarios/escuela.aspx/cargaEscuelas`
- `POST /guiahorarios/escuela.aspx/cargaModalidadPeriodos`
- `POST /guiahorarios/escuela.aspx/getdatosEscuelaAno`
- `POST /guiahorarios/estudiante.aspx/getdatos`
- `POST /guiahorarios/verano.aspx/getdatosVerano`

### Curriculum Catalog API (tecdigital - tds-curriculum-exp)
- `GET /tds-curriculum-exp/ajax/carga_sedes_json`
- `GET /tds-curriculum-exp/ajax/carga_carreras_json?id_sede=...`
- `GET /tds-curriculum-exp/ajax/carga_planes_json?id_sede=...&id_depto=...`
- `GET /tds-curriculum-exp/ajax/json_draw_angular?id_plan=...`

### Student Records / Schedule Guide API (tecdigital - tda-expediente-estudiantil)
- `POST /tda-expediente-estudiantil/ajax/combos/carga_periodos_tds_lib`
- `POST /tda-expediente-estudiantil/ajax/combos/carga_sedes_tds_lib`
- `POST /tda-expediente-estudiantil/ajax/combos/carga_carreras_tds_lib` (form: `id_sede=...`)
- `POST /tda-expediente-estudiantil/ajax/tabla_guia_horario?sede=...&carrera=...&periodo=...`

## Field Types Summary

| Field Type | Database Type | Notes |
|------------|---------------|-------|
| Primary Keys (catalog) | `BIGSERIAL` | Auto-incrementing BIGINT |
| Primary Keys (user tables) | `UUID` | References `auth.users(id)` |
| Foreign Keys to user | `UUID` | `user_id` in user-related tables |
| Timestamps | `TIMESTAMPTZ` | With timezone, default `NOW()` |
| Enums | `course_relation_type` | `PREREQUISITE`, `COREQUISITE`, `EQUIVALENT` |
| Enums | `student_course_status` | `PASSED`, `FAILED`, `IN_PROGRESS`, `WITHDRAWN`, `APPROVED` |
| Enums | `course_type` | `Curso Unico`, `Curso Comun`, `Electiva Unica` |
| Enums | `group_type` | `Regular`, `Semipresencial`, `Virtual`, `Asistida` |

## Entities and field dictionary

### `user`
Represents an application user/student profile. Only stores the carnet; all other user data (email, name) is in Supabase `auth.users`.

- `id` (PK): UUID FK to `auth.users(id)`. Primary key and foreign key to Supabase auth.
  - Source: Auto-generated by Supabase Auth, referenced via trigger.
- `carnet` (UK, nullable): Student ID.
  - Source: `1.4 getdatos` request body parameter `carnet`.
  - Example: `2024143009`.
  - User adds this via UI after registration.
- `created_at`, `updated_at`: App timestamps.

### `country`
- `id` (PK)
- `name`: Country name.
- `iso2_code` (UK): ISO-3166 alpha-2.

### `university`
- `id` (PK)
- `country_id` (FK → `country.id`)
- `name`
- `short_name`
- `created_at`, `updated_at`

### `campus`
Campus/site (“sede”). Codes are used across multiple APIs.

- `id` (PK)
- `university_id` (FK → `university.id`)
- `code` (UK): Campus code.
  - Sources:
    - `2.1 carga_sedes_json`: `sedes[].key`.
    - `3.2 carga_sedes_tds_lib`: `<span value='CA'>...`.
    - `1.3 getdatosEscuelaAno`: campus appears only by name (`DSC_SEDE`), so mapping is heuristic unless you maintain a name→code dictionary from `2.1/3.2`.
  - Examples: `CA`, `SJ`, `SC`, `AL`, `LM`.
- `name`: Campus full name.
  - Sources:
    - `2.1 carga_sedes_json`: `sedes[].data`.
    - `3.2 carga_sedes_tds_lib`: span inner text.
    - `1.3 getdatosEscuelaAno`: `DSC_SEDE` (uppercase sometimes).
  - Examples:
    - `Campus Tecnologico Central Cartago`
    - `Campus Tecnologico Local San Jose`
- `opened_on`, `closed_on`, `is_active`: Operational lifecycle (app-managed; helpful for plan availability rules).
- `created_at`, `updated_at`

### `academic_unit`
School/department that offers courses (escuela/departamento). Some may not have careers.

- `id` (PK)
- `university_id` (FK → `university.id`)
- `code` (UK): Department/school code.
  - Sources:
    - `1.1 cargaEscuelas`: `IDE_DEPTO`.
    - `3.3 carga_carreras_tds_lib`: `<span value='MA'>...` includes course-offering schools.
  - Examples: `CA`, `MA`, `ARH`.
- `name`: School/department name.
  - Sources:
    - `1.1 cargaEscuelas`: `DSC_DEPTO` (uppercase).
    - `3.3 carga_carreras_tds_lib`: span text.
    - `1.3 getdatosEscuelaAno`: `DSC_DEPTO`.
    - Example: `ESCUELA DE INGENIERIA EN COMPUTACION`.
- `created_at`, `updated_at`

### `career_program`
A degree program (“carrera”) attached to an `academic_unit`. In `tds-curriculum-exp`, the carreras list is effectively programs by campus.

- `id` (PK)
- `academic_unit_id` (FK → `academic_unit.id`)
- `code` (UK): Program code.
  - Source: `2.2 carga_carreras_json`: `carreras[].key`.
  - Examples: `AEN`, `CA`, `E`, `MC`.
- `name`: Program name.
  - Source: `2.2 carga_carreras_json`: `carreras[].data`.
  - Example: `Escuela de Ingeniería en Computación`.
- `academic_degree`: Catalog degree text.
  - Source: `2.4 json_draw_angular`: `academic_degree` (but that is per-plan; denormalize here only if stable; otherwise keep in `study_plan`).
- `created_at`, `updated_at`

### `career_campus`
Join table: which career programs are offered at which campuses.

- `id` (PK)
- `career_program_id` (FK → `career_program.id`)
  - Source: `2.2 carga_carreras_json?id_sede=...`.
- `campus_id` (FK → `campus.id`)
  - Source: same query parameter `id_sede`.
- `created_at`

### `academic_modality`
Catalog of modalities from `guiahorarios`.

- `id` (PK)
- `code` (UK): Modality code.
  - Source: `1.2 cargaModalidadPeriodos`: `IDE_MODALIDAD`.
  - Examples: `S` (Semestre), `V` (Verano), `B` (Bimestre), `C` (Cuatrimestre), `T` (Trimestre).
- `name`: Modality name.
  - Source: `1.2`: `NOMBRE`.
  - Example: `SEMESTRE`.
- `periods_per_year`: 
  - Source: `1.2`: `CANT_PERIODOS`.
  - Example: `2` for semester.

### `academic_term`
Specific “periodo” instance (year + modality + period no.). Needed for historical offerings and saved schedules.

- `id` (PK)
- `academic_modality_id` (FK → `academic_modality.id`)
  - Source: derived from key parsing of `3.1` or from `1.3` fields `IDE_MODALIDAD`.
- `year`: 
  - Sources:
    - `3.1 carga_periodos_tds_lib`: parse from `key` (e.g., `2026_S_1` → year=2026).
    - `1.3 getdatosEscuelaAno`: `NUM_ANO`.
- `period_number`:
  - Sources:
    - `3.1`: parse trailing `_1`.
    - `1.3`: `IDE_PER_MOD`.
- `external_key` (UK): Raw key representation.
  - Sources:
    - `3.1`: `key` like `2026_S_1`.
    - `1.5 getdatosVerano`: `PER_LECTIVO` like `VER-2025`.
  - Examples: `2026_S_1`, `VER-2025`.
- `display_name`: Human string.
  - Source: `3.1`: `data`.
  - Example: `2026 - Semestre 1`.
- `starts_on`, `ends_on`: Not in endpoints; optional institutional calendar integration.

### `study_plan`
Curriculum version for a given program.

- `id` (PK)
- `career_program_id` (FK → `career_program.id`)
  - Source: `2.3 carga_planes_json` is filtered by `id_depto` (program code).
- `academic_modality_id` (FK → `academic_modality.id`)
  - Source: `2.4 json_draw_angular`: `modality` (mapped to `academic_modality.code/name`).
- `external_plan_id` (UK): Numeric plan id.
  - Sources:
    - `2.3`: `planes[].key`.
    - `2.4`: `id_curriculum`.
  - Example: `412`.
- `name`: 
  - Source: `2.4`: `dsc_curriculum`.
  - Example: `INGENIERIA EN COMPUTACION-2022`.
- `academic_degree`:
  - Source: `2.4`: `academic_degree`.
  - Example: `Bachillerato Universitario`.
- `first_level_number`:
  - Source: `2.4`: `first_level`.
  - Example: `0`.
- `created_at`, `updated_at`

### `study_plan_campus`
Defines where/when a plan is valid (supports rule: campus created in 2010 cannot offer 1990 plan).

- `id` (PK)
- `study_plan_id` (FK → `study_plan.id`)
- `campus_id` (FK → `campus.id`)
- `valid_from`, `valid_to`: App-managed constraints.
- `created_at`

### `course`
Canonical course catalog.

- `id` (PK)
- `owning_academic_unit_id` (FK → `academic_unit.id`): Department that “owns” the course.
  - Sources:
    - `1.3 getdatosEscuelaAno`: `DSC_DEPTO` (name only; needs mapping to `academic_unit` by name).
    - `1.1 cargaEscuelas`: gives the authoritative code list.
- `code` (UK): Course code.
  - Sources:
    - `1.3`: `IDE_MATERIA`.
    - `2.4`: `courses[].id_course`.
    - `1.5`: `IDE_MATERIA`.
    - `3.4`: HTML table “Código”.
  - Examples: `IC1802`, `MA0101`, `CA2125`, `FH0178`.
- `name`: Canonical course name.
  - Sources:
    - `2.4`: `courses[].name` (lowercase).
    - `1.3`: `DSC_MATERIA`.
    - `1.5`: `DSC_MATERIA`.
    - `3.4`: HTML column “Materia”.
  - Examples: `introducción a la programación`, `Elementos de computación`, `MATEMÁTICA GENERAL`.
- `default_credits`:
  - Sources:
    - `2.4`: `courses[].credits`.
    - `1.3`: `CAN_CREDITOS`.
    - `3.4`: HTML “Créditos”.
  - Examples: `3`, `2`, `4`.
- `default_weekly_hours`:
  - Sources:
    - `2.4`: `courses[].hours`.
    - `1.3`: `HORAS`.
  - Examples: `4`, `5`.
- `created_at`, `updated_at`

### `study_plan_level`
Explicit period/level inside a plan (e.g., “Semestre 0”, “Semestre 1”).

- `id` (PK)
- `study_plan_id` (FK → `study_plan.id`)
- `level_number`: Parsed int ordering.
  - Source: `2.4`: `levels[].id` like `Semestre 1`.
- `level_label`: Raw label.
  - Source: `2.4`: `levels[].id`.
- `created_at`

### `study_plan_level_course`
Join table: which courses are in which plan level.

- `id` (PK)
- `study_plan_level_id` (FK → `study_plan_level.id`)
- `course_id` (FK → `course.id`)
- `credits`:
  - Source: `2.4`: `courses[].credits`.
- `weekly_hours`:
  - Source: `2.4`: `courses[].hours`.
- `sort_order`: UI ordering (app-managed; stable ordering not guaranteed by API).

### `course_relation`
Constraints within a study plan: prerequisites, corequisites, equivalents.

- `id` (PK)
- `study_plan_id` (FK → `study_plan.id`)
- `from_course_id` (FK → `course.id`)
- `to_course_id` (FK → `course.id`)
- `relation_type`: Enum.
  - Sources:
    - `2.4`: `courses[].requirements[]` → `PREREQUISITE`
    - `2.4`: `courses[].co_requirements[]` → `COREQUISITE`
    - `2.4`: `courses[].equivalent[]` (when actual codes like `IC1800`) → `EQUIVALENT`
  - Examples:
    - `IC1802` equivalent `IC1800`.
    - `MA0101` required_by → inverse relation; can be derived, not stored.

### `professor`
- `id` (PK)
- `full_name` (UK)
  - Sources:
    - `1.3`: `NOM_PROFESOR`.
    - `1.5`: `PROFESOR`.
    - `3.4`: HTML column “Profesor”.
  - Examples:
    - `MATA RODRIGUEZ WILLIAM`
    - `CASTRO MORA JOSE`
    - `Schmidt Peralta Jeff`
- `created_at`

### `course_offering`
A course being offered at a campus during a term (header-level). Supports history.

- `id` (PK)
- `course_id` (FK → `course.id`)
- `campus_id` (FK → `campus.id`)
  - Sources:
    - `3.4`: request parameter `sede`.
    - `1.3/1.5`: campus name (`DSC_SEDE`) must map to `campus.code`.
- `academic_unit_id` (FK → `academic_unit.id`)
  - Sources:
    - `3.4`: request parameter `carrera` represents the publishing school/department code from Student Records.
    - `1.3`: `DSC_DEPTO` can be used to derive a publishing unit name but does not provide a code directly.
- `academic_term_id` (FK → `academic_term.id`)
  - Sources:
    - `3.4`: request parameter `periodo` (via `academic_term.external_key`).
    - `1.3`: term components (`NUM_ANO`, `IDE_MODALIDAD`, `IDE_PER_MOD`) normalized into the same external key format.
    - `1.5`: `PER_LECTIVO` (e.g., `VER-2025`).
- `course_name_snapshot`:
  - Sources: `1.3 DSC_MATERIA`, `1.5 DSC_MATERIA`, `3.4 Materia`.
- `credits_snapshot`:
  - Sources: `1.3 CAN_CREDITOS`, `3.4 Créditos`.
- `weekly_hours_snapshot`:
  - Source: `1.3 HORAS`.
- `course_type`:
  - Source: `3.4 Tipo Materia` (`Curso Unico`, `Curso Comun`, `Electiva Unica`).
- Uniqueness: `(course_id, campus_id, academic_unit_id, academic_term_id)`
- `created_at`

### `course_offering_group`
A specific section/group for an offering.

- `id` (PK)
- `course_offering_id` (FK → `course_offering.id`)
- `group_code`:
  - Sources:
    - `1.3`: `IDE_GRUPO` (number).
    - `1.5`: `NUM_GRUPO` (string like `"1"`).
    - `3.4`: HTML “Grupo” (e.g., `01`, `02`).
- `group_type`:
  - Sources:
    - `1.3`: `TIPO_CURSO` (`Regular`, `Semipresencial`, `Virtual`).
    - `3.4`: "Tipo Grupo" (same).
    - `1.5`: `PRESENCIAL` (`P`/`V`) can map to `Regular/Virtual` depending on business rules.
  - Enum values: `Regular`, `Semipresencial`, `Virtual`, `Asistida`
- `classroom`:
  - Source: `3.4` column “Aula” (e.g., `B6-04`, or `No disponible`).
- `capacity`:
  - Sources:
    - `1.5`: `CUPO_GRUPO`.
    - `3.4`: “Cupo”.
- `reserved_seats`:
  - Sources:
    - `3.4`: “Reservados”.
    - `1.3`: may be derivable from reservation fields if implemented.
- `enrolled_count`:
  - Source: `1.5`: `CANT_MATRICULADOS`.
- `created_at`

### `course_offering_group_professor`
Join because a group may have multiple professors.

- `id` (PK)
- `course_offering_group_id` (FK → `course_offering_group.id`)
- `professor_id` (FK → `professor.id`)
- `created_at`

### `course_offering_meeting`
Normalized schedule rows (day/time). Needed because `getdatosEscuelaAno` returns one row per meeting.

- `id` (PK)
- `course_offering_group_id` (FK → `course_offering_group.id`)
- `weekday`:
  - Sources:
    - `1.3`: `NOM_DIA` (`MARTES`, `MIERCOLES`, ...).
    - `1.5`: columns `LUNES`..`SABADO` contain time ranges.
    - `3.4`: `Horario` like `Martes - 7:30:9:20`.
  - Example: `2` for Tuesday.
- `starts_at`, `ends_at`:
  - Sources:
    - `1.3`: `HINICIO`, `HFIN`.
    - `3.4`: parse `Horario`.
    - `1.5`: parse each day string like `11:30 - 12:45`.
- Uniqueness: `(course_offering_group_id, weekday, starts_at, ends_at)`
- `created_at`

### `course_offering_reservation`
Captures reserved seats with optional targeting constraints.

- `id` (PK)
- `course_offering_group_id` (FK → `course_offering_group.id`)
- `campus_id` (FK → `campus.id`, nullable)
  - Source: `1.3`: `RESERVA_SEDE` (name; map to campus).
- `academic_unit_id` (FK → `academic_unit.id`, nullable)
  - Source: `1.3`: `RESERVA_DEPTO` (name; map to unit code).
- `study_plan_id` (FK → `study_plan.id`, nullable)
  - Source: `1.3`: `RESERVA_PLAN` (external plan id; map to `study_plan.external_plan_id` where possible).
- `reserved_seats`:
  - Source: `3.4` HTML column `Reservados`.
- Uniqueness: `(course_offering_group_id, campus_id, academic_unit_id, study_plan_id)`

### `user_study_plan`
User's declared plan context (needed for eligibility checks).

- `id` (PK)
- `user_id` (FK → `user.id`, UUID): Foreign key to Supabase auth user.
- `study_plan_id` (FK → `study_plan.id`)
- `campus_id` (FK → `campus.id`)
- `entry_year`:
  - Source: derived from `user.carnet` first 4 digits (rule in `1.4` notes).
  - Example: `2024`.
- `started_on`, `ended_on`, `is_active` (app-managed)
- `created_at`

### `student_course_record`
Stores user-grade/approval history per course (used for eligibility and filtering offerings).

- `id` (PK)
- `user_id` (FK → `user.id`, UUID): Foreign key to Supabase auth user.
- `study_plan_id` (FK → `study_plan.id`)
- `course_id` (FK → `course.id`)
- `academic_term_id` (FK → `academic_term.id`)
- `status`, `grade`, `approved`, `recorded_at`: App-managed; endpoints in `DETALLES.md` do not provide grade transcript details, but requirements demand this storage.

### `saved_schedule`
User-defined schedule collection (not enrollment).

- `id` (PK)
- `user_id` (FK → `user.id`, UUID): Foreign key to Supabase auth user.
- `name`:
  - Source: app input.
  - Example: `IS2026`.
- `academic_term_id` (FK → `academic_term.id`)
  - Source: app choice; typically from `3.1 period keys`.
- `created_at`, `updated_at`

### `saved_schedule_item`
Chosen groups inside a saved schedule.

- `id` (PK)
- `saved_schedule_id` (FK → `saved_schedule.id`)
- `course_offering_group_id` (FK → `course_offering_group.id`)
- `created_at`

## Real example payload mappings (from `DETALLES.md`)

### Example: `academic_unit` from `cargaEscuelas`
- `IDE_DEPTO=MA` → `academic_unit.code=MA`
- `DSC_DEPTO=ESCUELA DE MATEMATICA` → `academic_unit.name=...`

### Example: `academic_modality` from `cargaModalidadPeriodos`
- `IDE_MODALIDAD=S`, `NOMBRE=SEMESTRE`, `CANT_PERIODOS=2`

### Example: Course offering meeting from `getdatosEscuelaAno`
Input: `escuela=CA`, `ano=2026`
- `IDE_MATERIA=IC6200` → `course.code=IC6200`
- `DSC_MATERIA=Inteligencia artificial` → `course_offering.course_name_snapshot`
- `IDE_GRUPO=40` → `course_offering_group.group_code=40`
- `NOM_DIA=MIERCOLES` + `HINICIO=15:00` + `HFIN=16:50` → `course_offering_meeting` row
- `TIPO_CURSO=Semipresencial` → `course_offering_group.group_type`
- `NOM_PROFESOR=CASTRO MORA JOSE` → `professor.full_name`

### Example: Term key from `carga_periodos_tds_lib`
- `key=2026_S_1` → year=2026, modality=S, period_number=1

### Example: Study plan details from `json_draw_angular`
- `id_curriculum=412` → `study_plan.external_plan_id=412`
- `dsc_curriculum=INGENIERIA EN COMPUTACION-2022` → `study_plan.name`
- `levels[].id=Semestre 1` → `study_plan_level.level_label`
- `courses[].id_course=IC1802` → `course.code`
- `courses[].equivalent=[{"id":"IC1800"}]` → `course_relation(relation_type=EQUIVALENT)`

### Example: Offerings from `tabla_guia_horario` (HTML)
Row example:
- Código: `IC1802`
- Materia: `Introducción a la programación`
- Grupo: `01`
- Créditos: `3`
- Horario: `Martes - 7:30:9:20`
- Aula: `B6-04`
- Profesor: `Schmidt Peralta Jeff`
- Cupo: `23`
- Tipo Materia: `Curso Unico`
- Tipo Grupo: `Regular`
- Reservados: `1`

### Example: Summer offerings from `getdatosVerano`
- `PER_LECTIVO=VER-2025` → `academic_term.external_key=VER-2025`
- `NUM_GRUPO=1`, `CUPO_GRUPO=25`, `CANT_MATRICULADOS=15`
- `MARTES="11:30 - 12:45"`, `JUEVES="11:30 - 12:45"` → two meeting rows
